# Section patterns

Choose a layout for the actual content. Use at most two patterns with the same structure next to each other. Preserve the plan's tokens and the user's requested section count.

- Hero: text-led introduction with one action; asymmetric text beside supplied work; compact identity masthead above a project index.
- Projects: wide project rows with summary and real links; alternating case-study bands; compact two-column index when content supports it.
- Publications: chronological citation list; year groups with document links; compact table with title, authors and venue. Never alter citation facts.
- Timeline: one vertical date column beside descriptions; alternating bands for long entries; compact grouped experience list. Mobile uses a single column.
- Skills: grouped text lists with meaningful headings; short tool or discipline rows; narrative explanation tied to actual projects. No invented proficiency percentages.
- Contact: direct links and a brief invitation; inline footer navigation; a standalone contact band. Use supplied URLs only. Static builds cannot add submission forms.

Motion: a short opacity/transform entrance can reinforce hierarchy, but content must be visible without JavaScript and with reduced motion. Use the existing scoped builder animation for pen edits when its constraints require it.
